## 수정 기록 1 — 병해 자료 대조 (이팝나무 연결 확인)

- 발견한 문제: 병해별 증상·대상 수종·위험도가 AI가 일반 지식으로 만든 초안이라 근거가 확인되지 않았다. 특히 흰가루병과 미국흰불나방을 이팝나무에 연결한 부분이 맞는지 의심스러웠다. 관리 요령과 방제 적기(월)도 출처 없이 적혀 있었다.
- AI에게 전달한 요청: "병해별 증상, 대상 수종, 위험도는 국립산림과학원 「생활권 수목 병해충 도감」과 나무병원협회자료, 수목보호협회 등의 자료와 대조해서 확인해줘, 특히 흰가루병을 이팝나무에, 미국흰불나방을 이팝나무에 연결한 부분은 꼭 확인해줘"
- 수정 후 테스트 결과:
  - `이팝나무` + S1(흰 가루) → 흰가루병이 나오지 않고 "일치하는 병해가 없습니다" 표시 (기대 결과와 일치)
  - `이팝나무` + S21, S22 → 이팝나무 녹병 2/2 (100%) · 조치 필요 (손계산과 일치)
  - 기존 완료 기준 사례(`기타·모름` + S1, S19 → 흰가루병 100%, `은행나무` + S7, S17 → 제설염 피해 67%)가 수정 후에도 같은 결과
- 수정 이유: 실무자가 쓰는 진단 도구이므로 근거 없는 연결은 오진으로 이어진다. 자료 대조 결과, 이팝나무 흰가루병은 보고를 찾지 못해 삭제했다. 이팝나무 녹병은 2018년 강진 가로수 대발생과 2020년 첫 보고 논문이 있어 추가했다. 이팝나무 미국흰불나방은 지자체 긴급 방제 사례와 나무병원 자료(물푸레나무과 방제 그룹)가 있어 유지했다. 「생활권 수목 병해충 도감」 원문과 협회 자료는 온라인에서 찾지 못해, 직접 확인하지 못한 4건을 '남은 확인 과제'로 남겼다.

## 수정 기록 2 — 목록에 없는 증상 기록, 부위별 영역 구분

- 발견한 문제: 체크 목록에 없는 증상이 보여도 남길 방법이 없었다. 또 증상 체크가 부위 제목만 있는 한 줄 목록이라 잎·가지·줄기·뿌리주변이 한눈에 구분되지 않았다.
- AI에게 전달한 요청: "선택한 가로수의 병해 진단 목록에 없는 증상을 기록할 수 있는 기능과 증상체크에서 잎, 가지, 줄기, 뿌리주변 항목이 별도 영역으로 구분되도록 수정해줘"
- 수정 후 테스트 결과:
  - 증상 체크가 색이 다른 상자 4개(🍃 잎, 🌿 가지, 🪵 줄기, 🌱 뿌리·주변)로 나뉘고, 상자마다 기록 칸이 1개씩 있음 (크롬 캡처로 PC 2열, 휴대폰 1열 확인)
  - 체크 없이 '잎' 기록 칸에만 입력하고 진단 → 결과에 "[잎] …"과 "일치하는 병해가 없습니다" 표시
  - 기록 칸에 `<b>` 태그를 입력 → 글자 그대로 표시되고 화면 모양이 바뀌지 않음
  - [결과 복사] 텍스트에 '기록한 기타 증상' 포함, [초기화] 후 기록 칸이 비워짐
- 수정 이유: 현장에서는 목록 밖 증상도 나무병원 상담에 필요한 정보이므로 기록할 수 있어야 한다. 다만 자유롭게 적은 문장은 병해와 자동으로 맞춰 볼 수 없어 일치율 계산에는 넣지 않고 상담용 메모로만 쓰도록 했다. 부위별 영역 구분은 나무를 아래에서 위로 살피며 체크할 때 찾기 쉽게 하기 위해서다.

## 수정 기록 3 — 수종별 증상 체크 항목 구성

- 발견한 문제: 기획 단계에서 "수종 선택 → 부위별 체크박스"로 정했지만, 실제 HTML은 어떤 수종을 골라도 22개 증상을 모두 보여 줬다. 수종에 따라 바뀌는 것은 진단 대상 병해뿐이어서 기획 의도와 달랐다.
- AI에게 전달한 요청: "수종별로 증상체크 항목이 별도로 구성되었다고 기획서에는 작성되었는데, 실제로 구현된 HTML에는 수종별로 증상체크 항목이 별도로 구성된 것으로 보이지 않은데, 꼼꼼하게 확인해서 수정해줘"
- 수정 후 테스트 결과:
  - 수종 선택 전: 체크박스 0개, "① 수종을 먼저 선택하면…" 안내만 표시
  - 수종별 체크박스 수: 은행 9 · 벚 16 · 느티 12 · 양버즘 14 · 이팝 13 · 기타·모름 22 (기획서 '수종별 증상 체크 항목' 표와 일치)
  - `벚나무`에서 S3(버즘나무방패벌레 증상), `이팝나무`에서 S1(흰가루병 증상)이 목록에 없음
  - 모든 수종에서 도복 위험 증상 S13~S16 표시
  - 목록 위에 "수종 이름 — 진단 대상 병해 ○개 · 증상 체크 항목 ○개"와 대상 병해 이름 표시
- 수정 이유: 해당 수종에 생기지 않는 병의 증상까지 보여 주면 체크할 항목이 늘어나 현장에서 느리고 헷갈린다. 수종에 맞는 항목만 보여 주어야 기획한 사용 흐름과 맞다. 수종별 항목은 병해-증상 연결표에서 자동으로 만들어지게 해서, 나중에 연결표를 고치면 체크 목록도 함께 바뀌도록 했다. 이 과정에서 체크할 수 없게 된 완료 기준 2개("벚나무 + S3", "이팝나무 + S1")를 "목록에 없다"는 기준으로 바꿨다.

## 수정 기록 4 — 소나무 삭제, 배롱나무 추가

- 발견한 문제: 수종 목록에 소나무가 있었는데, 실제 관리할 가로수로 배롱나무가 더 필요했다. 소나무재선충병은 일반 진단보다 신고 대상이라 이 체크리스트의 목적과도 거리가 있었다.
- AI에게 전달한 요청: "소나무는 삭제하고 배롱나무를 추가해서 증상체크를 완성해줘."
- 수정 후 테스트 결과:
  - 수종 버튼에 소나무가 없고 배롱나무가 있음. 페이지 안에서 소나무·솔잎·송진 관련 내용 0건
  - `배롱나무` 선택 → 진단 대상 병해 6개, 체크 항목 13개(잎 5, 가지 2, 줄기 4, 뿌리·주변 2)
  - `배롱나무` + S23, S6 → 주머니깍지벌레 2/2 (100%) · 조치 필요, 깍지벌레·그을음병 1/3 (33%)
  - `배롱나무` + S24, S19 → 배롱나무 갈색점무늬병 2/2 (100%) · 관찰
  - `배롱나무` + S14 → 줄기 썩음 1/4 (25%) · 즉시 전문가, 도복 경고 표시
  - 어느 병해에도 연결되지 않은 증상 없음(도복 전용 S16 제외)
- 수정 이유: 사용자 요구에 맞춰 수종을 바꿨다. 배롱나무 병해는 자료로 확인한 것만 넣었다. 흰가루병(나무병원 자료의 발생 수종), 주머니깍지벌레(배롱나무 가로수 극심 피해 논문, 연 2회 발생), 갈색점무늬병(한국 발생 기록과 해외 증상 자료)이다. 갈색점무늬병의 국내 공식 병명은 확인하지 못해 남은 과제로 기록했다. 이전 대조 기록과 헷갈리지 않도록 D10·S8·S18 번호는 다시 매기지 않고 비워 두었다.

## 수정 기록 5 — 위험도 등급 설명 추가

- 발견한 문제: 결과 카드에 '관찰 / 조치 필요 / 즉시 전문가' 배지만 있고 각 등급이 무엇을 뜻하는지, 무엇을 해야 하는지 설명이 없었다.
- AI에게 전달한 요청: "진단결과에 대한 평가의 위험도 등급(관찰 / 조치 필요 / 즉시 전문가)에 대한 간단한 설명을 이 진단결과칸에 추가해줘"
- 수정 후 테스트 결과:
  - 결과가 나오면 후보 카드 아래에 '위험도 등급 안내'(세 등급의 뜻과 대응) 표시
  - `은행나무` + S7, S17, S11 → '조치 필요', '즉시 전문가' 줄에 "← 이번 결과" 강조, '관찰' 줄은 강조 없음
  - `배롱나무` + S24, S19 → '관찰'만 강조
  - 증상 없이 진단(오류 안내가 나오는 경우) → 등급 안내 표시 안 함
  - [결과 복사] 텍스트에 등급 요약 한 줄 포함, 크롬 캡처로 화면 확인
- 수정 이유: 등급의 뜻을 알아야 사용자가 직접 관리할지, 나무병원에 의뢰할지 판단할 수 있다. 이것이 페이지의 사용 목적이다. 도복 경고 배너가 등급과 따로 나온다는 점도 함께 적어 혼동을 줄였다.

## 수정 기록 6 — 수종 변경 시 증상 체크 초기화

- 발견한 문제: 수종을 선택해 증상을 체크한 뒤 다른 수종을 선택하면 이전 체크가 그대로 남았다. 수정 기록 3에서 두 수종에 공통인 증상의 체크를 유지하도록 만든 동작 때문이었다.
- AI에게 전달한 요청: "수종을 선택하고 증상체크 후 다른 수종을 선택하면 초기화가 안되고 이미 전에 선택한 증상이 체크가 남아있는 오류가 있어요. 다른 수종을 선택하면 증상체크는 초기화되도록 수정해줘"
- 수정 후 테스트 결과:
  - `벚나무`에서 S1, S11, S13 체크 + 기록 칸 입력 + 진단 → `느티나무`로 변경 → 체크 0개, 기록 칸 빈칸, 결과 창 닫힘. 느티나무에도 있는 S1·S11·S13 모두 해제
  - 변경 시 "수종을 바꿔 이전 증상 체크와 기록을 초기화했습니다." 안내 표시
  - 체크나 기록 없이 수종만 바꾸면 안내 문구 없음
  - 이미 선택된 수종 버튼을 다시 누르면 체크 유지
  - 변경 후 새로 체크하고 진단하면 정상 결과 표시, 수종별 체크박스 수 변화 없음
- 수정 이유: 수종을 바꾼다는 것은 다른 나무를 진단한다는 뜻이다. 이전 나무의 체크가 남으면 잘못된 진단 결과가 나올 수 있다. 같은 이유로 기록 칸 내용과 이전 결과도 함께 지웠다.

### 수정 기록 7 — 디자인 개선(v2): 다크 모드, 도감 연결, 구상나무 디자인 시스템·Pretendard 적용

- 발견한 문제:
  - 다크 모드가 없어 어두운 실내나 야간 현장에서 화면이 지나치게 밝았다.
  - 증상 체크 안내문 "① 수종을 먼저 선택하면…"의 '①'이 ① 수종 선택 단계 번호와 겹쳐 헷갈렸다.
  - 진단 결과 카드와 미니 도감이 서로 연결되지 않아, 후보 병해의 자세한 설명을 보려면 도감까지 스크롤해서 직접 찾아야 했다.
  - 증상 체크와 병해 목록 디자인이 단조로워, 함께 비교한 GPT 결과물보다 부위·항목 구분이 약했다.
  - '양버즘나무(플라타너스)' 버튼은 이름이 길어 화면 폭에 따라 아무 곳에서나 줄이 바뀌었다.
  - 화면 디자인이 N+연구소 작업에서 쓴 디자인 시스템과 달랐고, 기기 기본 글꼴이라 기기마다 글자 모양이 달랐다.
- AI에게 전달한 요청: "가로수병해진단 체크리스트 홈페이지를 계속해서 수정하려고 해, 첨부한 가로수병해진단_v1.html, 기획서_v1.md파일을 단계별로 수정하면서 성능을 높이려고 해, 전반적으로 GPT 결과물 html 파일을 공유할테니, 디자인 개선에 참고해서 적용해줘, 두개의 캡처본도 GPT 결과물이야 / 1. 다크모드를 적용해줘 2. '수종을 먼저 선택하면 그 수종에 맞는 증상 체크 항목이 나타납니다.' 원괄호 1번 제거해줘 3. 병해목록 미니도감과 진단결과와의 연결가능한 것은 연결해줘 4. gpt가 만든 캡처본처럼 증상체크 디자인을 변경해줘 5. 두번째 캡처본처럼 병해목록 디자인을 변경해줘 6. GPT양식은 디자인을 변경하는데 참고만해줘 7. 양버즘나무(플라타너스)는 괄호(플라타너스)가 두줄로 표현되게 변경해줘 8. 디자인은 N+연구소 작업하면서 활용한 디자인시스템을 적용해주고, 글꼴은 pretendard 폰트를 사용해줘"
- 수정 후 테스트 결과 (`가로수병해진단_v2.html`, 기획서 `기획서_v2.md`):
  - **기능 유지(회귀 테스트)**: 수정 기록 1~6에서 쓴 테스트를 그대로 다시 실행했다.
    - 수종별 체크 항목 수(은행 9·벚 16·느티 12·양버즘 14·이팝 13·배롱 13·기타 22)가 v1과 같았다.
    - 완료 기준의 일치율·정렬(흰가루병 2/2(100%), 제설염 피해 2/3(67%), 이팝나무 녹병 2/2, 주머니깍지벌레 2/2 + 깍지벌레·그을음병 1/3, 배롱나무 갈색점무늬병 2/2)과 위험도 "← 이번 결과" 강조, 수종 변경 시 초기화, 결과 복사 내용이 v1과 같았다.
  - **다크 모드**:
    - 기기가 라이트일 때 처음 열면 라이트로 시작한다. [다크 모드]를 누르면 화면 전체가 어두워지고 버튼이 [라이트 모드]로 바뀌며, 선택이 브라우저에 저장된다.
    - 기기가 다크이고 저장된 값이 없으면 다크로 시작한다. 기기가 다크여도 저장된 값이 라이트면 라이트로 시작한다.
    - 크롬 캡처로 라이트·다크 화면을 모두 확인했다.
  - **'①' 제거**: 수종 선택 전 안내문이 "수종을 먼저 선택하면 그 수종에 맞는 증상 체크 항목이 나타납니다."로 나오고, '①'이 없다.
  - **도감 연결**: `벚나무` + S2·S19·S13으로 진단했다.
    - 결과 카드 순서는 D2(1위)·D1(2위)·D11(3위)이고, 도감의 D2·D1·D11에 '이번 진단 1위·2위·3위'가 붙는다.
    - 펼친 D2의 대표 증상 S2·S19에 ✓가 붙는다.
    - 1위 카드의 [미니 도감에서 자세히 보기]를 누르면 접혀 있던 D2가 펼쳐지며 그 위치로 이동하고 강조된다. D2 안의 [진단 결과 1위 카드로 돌아가기]를 누르면 1위 카드로 돌아와 강조된다.
    - 다시 진단해도 펼쳐 둔 도감 항목이 그대로 펼쳐져 있다.
    - 벚나무를 고르면 '벚나무 진단 대상' 표시가 8개 붙고, 느티나무로 바꾸면 5개로 바뀌며 순위·✓ 표시가 사라진다. [초기화]를 누르면 모든 표시가 사라진다.
  - **증상 체크 디자인**:
    - 부위별 카드 4개(잎=초록, 가지=파랑, 줄기=갈색, 뿌리·주변=노랑)에 아이콘·이름·개수 머리줄(예: 양버즘나무 잎 7개)과 줄 구분선이 있다.
    - 체크한 줄은 옅은 배경색으로 바뀐다.
    - 기록 칸에 3글자를 입력하면 "3/300"이 표시된다.
  - **병해 목록 디자인**: 병해마다 둥근 상자로 나뉘고 "D1 · 흰가루병 [관찰]" 형식으로 보인다. 펼치면 화살표가 돌아간다.
  - **양버즘나무 두 줄**: 버튼에 '양버즘나무' 아래 줄로 '(플라타너스)'가 작게 표시되고, 다른 버튼과 높이가 같다. 화면 낭독용 이름은 '양버즘나무(플라타너스)' 한 줄로 유지된다.
  - **디자인 시스템·글꼴**:
    - 색(#2E7D57 초록, 초록 기운 그레이), 간격(4px 단위), 모서리(8·12·16·24px)를 구상나무 디자인 시스템 값으로 적용했다.
    - 크롬 캡처에서 Pretendard 글꼴로 표시되는 것을 확인했다.
    - 시스템 규칙("이모지를 쓰지 않는다")에 따라 페이지 안의 이모지를 선 아이콘으로 바꿨다.
  - **스마트폰 375px**: 가로 스크롤이 없다. 수종 버튼은 2열이고, [다크 모드] 버튼 글자는 한 줄로 보인다(처음 캡처에서 두 줄로 꺾이는 것을 발견해 고쳤다).
- 수정 이유:
  - 다크 모드는 어두운 곳에서 눈부심을 줄이고, 기기 설정을 따르게 해 처음 여는 사용자도 익숙한 화면으로 시작하게 했다.
  - '①'은 단계 번호와 헷갈리지 않게 지웠다.
  - 도감 연결은 결과를 본 실무자가 그 병해의 대상 수종·대표 증상·관리 요령을 바로 확인하고 결과로 돌아올 수 있게 하려는 것이다. 사용 목적인 '직접 관리할지, 나무병원에 의뢰할지 판단'을 빠르게 한다.
  - GPT 결과물은 화면 모양(부위별 카드, 글자 수, 병해 상자)만 참고하고, 검증을 마친 v1의 구조·데이터·문구는 그대로 두었다. 비교 테스트에서 Claude 결과물을 고른 근거(인쇄 2쪽, 22px 체크박스)도 그대로 유지했다.
  - 디자인 시스템과 Pretendard는 기관 결과물끼리 같은 인상을 주고 기기마다 글자 모양이 달라지지 않게 하려고 적용했다.
  - 디자인 시스템에는 라이트 색만 있어서, 다크 모드 색은 같은 초록·그레이 계열에서 골라 정하고 기획서에 그 사실을 적었다.
  - Pretendard는 인터넷(jsDelivr)으로 불러오므로 기획서의 '반드시 지킬 조건'에 "사진과 글꼴만 인터넷 주소로 불러오며, 없어도 기본 글꼴로 동작한다"는 예외를 추가하고, 출처와 라이선스(SIL OFL 1.1)를 바닥글과 기획서에 적었다.
